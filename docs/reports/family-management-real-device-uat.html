真实 PostgreSQL 多连接交错方法

  1. 只在一次性数据库建立 3 成员测试家庭，保存脱敏 group/member 标识与当前 key_epoch。
  2. 连接 G（barrier）执行 BEGIN; LOCK TABLE groups IN ACCESS EXCLUSIVE MODE;，暂不提交。
  3. 按用例指定顺序，从两台真机或两个带真实 Ed25519 签名的客户端同时发起操作；确认两个 API 请求均在 PostgreSQL 等待。
  4. 用独立观察连接查询 pg_stat_activity，记录等待事件与 query start；然后在 G 执行 COMMIT;。
  5. 核对 HTTP 结果、groups.key_epoch/key_rotation_state/revision、group_members.status/role/removal_reason、目标密钥信封和 control event。交换请求入队顺序重复。
  6. 每种交错至少 10 轮；允许两种合法串行顺序，不允许部分提交、重复 fan-out、epoch 倒退、收件集错误、悬挂 pending 或死锁。
禁止：不要在生产库执行 down migration、表锁、故障注入或明文 SQL 取证；不要把数据库 URL、Push token、p8/FCM 凭据放进截图或导出的 JSON。

B 在线/后台/被杀三态接收 member_left；随后尝试 check、WS、events、push/pull/ack/key request。		本地清家庭并停 transport；Server active membership gate 全拒绝；无新 epoch key/密文；旧 Push 不导航回家庭。
MEM-04P0剩余成员新 epoch 收敛
C 离线经历 B 被移除，随后上线；A/C 各创建新数据。		C 安装精确 envelope 和新 epoch；旧 ciphertext queue 清理后从 semantic outbox 重加密；A/C 新数据双向可见，B 不可见。
MEM-05P0A → B 转让 Owner
三成员 active，执行双确认转让；网络中断后重试同 request。覆盖：F19		B 成唯一 owner，A/C member；epoch+1；所有 active recipient 有且仅有一个新 envelope；幂等重试不二次增 epoch。
MEM-06P0转让后权限即时更新
A/B 前台、后台、冷启动分别检查 UI 与 API。		B 获得 Owner 控制；A 立即失去；旧 role Push/revision 不反转；Server 以权威 role 拒绝旧 Owner 越权。
MEM-07P0成员自助离场
C 离线存变更后 leave；强杀 C；Owner B 暂时离线。覆盖：F19		C 进入 removed/left；group 为 rotation pending 且 epoch 未提前推进；requestId/target 持久；C 本地安全离场。
MEM-08P0rotation pending fail closed
在 B 完成轮换前，A/B 尝试普通 push，C 尝试 pull/key。		普通 push 明确失败/排队，不以旧 key 继续；C 无访问；控制面仍可恢复；UI 可提示同步待恢复而非假 synced。
MEM-09P0Owner 完成 pending rotation
B 上线完成；在提交/响应边界断网并重启。		B/A 收到新 epoch；state 回 ready；语义 outbox 重放；重复 completion 幂等；无 C envelope；同步恢复。
MEM-10P0解散家庭
当前 Owner 解散；其他成员分别在线、后台、被杀。		所有设备最终清 active group、key 和 transport；旧 group check 无效；可创建/加入新家庭；旧数据不误并入新 group namespace。
MEM-11P0Group key recovery
让 active B 丢失当前 group key（测试构建/fault injection），由 active A 响应 key request；覆盖 kill/retry。覆盖：F17		Relay 只转发目标密封 key；epoch 匹配；B 恢复后 revalidate membership 再 active；removed/pending responder 被拒。
MEM-12P1Key recovery 不可用
所有能提供当前 key 的设备离线直至 request 过期。		明确说明 zero-knowledge 无法由 Server 恢复；可重试或安全离开/解散；不自动生成错误 key、不越过 awaiting-key。
